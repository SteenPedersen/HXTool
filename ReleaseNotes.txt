HXTool Release Notes
====================
Version 26.09
-------------

LOCAL CATALOG — RULE GROUPS
---------------------------
  - Replaced the Local Catalog DataTable with a collapsible group tree view. Rules
    are organized into groups (default "Root"); each group's expand/collapse state
    is remembered.
  - Create and delete groups; deleting a group moves its rules back to Root.
  - Drag-and-drop rules between groups. Shift-click to multi-select and drag all
    selected rules into a group at once.
  - Rules render in an aligned, sortable table (Name, Created, Platforms,
    Description, presence/execution match counts). Created shows full date and
    time; column widths auto-fit their content.
  - The catalog search/filter box now matches the Server Rules search field in
    font, colour and size.


IOC HUNT (NEW)
--------------
  - New "IOC Hunt" page under Enterprise Search: paste raw threat intel,
    auto-detect IOC types (SHA256, SHA1, MD5, IP, DNS/domain, URL, registry,
    process/file, command line) with colour-coded highlighting, then submit HX
    Enterprise Searches.
  - Force a type per line with a prefix — e.g. "url,", "domain,", "filename,",
    "file_path_name,", "md5,", "sha1,", "sha256,". A second comma starts a
    comment, e.g. "filename,evil.csv,notes here" only takes evil.csv.
  - Added SHA1 as a detected/searchable hash type.
  - Run-now hunts submit synchronously so per-type success (with search ID) and HX
    errors are shown directly in the UI.


IOC HUNT — SETTINGS & FIELD MAPPING (ADMIN)
-------------------------------------------
  - New Admin menu items: "IOC Hunt detection settings" and "IOC Hunt field
    mapping". The detection settings previously on the HXTool Settings page were
    moved to this dedicated page.
  - Field mapping: configure which HX Enterprise Search field(s) each IOC type is
    searched against (multiple fields per type). Available operators adapt to the
    field's data type (text vs numeric/date vs boolean). Stored in a local file
    (ioc_hunt_fields.json) that can be edited and saved at any time.
  - Detection settings are shown in a two-column layout; field mapping in a
    multi-column layout.


LOCAL CATALOG — HUNT (ENTERPRISE SEARCH)
----------------------------------------
  - Hunting selected Local Catalog rules now builds HX field/query Enterprise
    Searches (the same mechanism as the HX console field picker) by mapping each
    condition's event token to the corresponding HX search field, so hunts return
    results against indexed audit data.
  - One search is created per distinct field to satisfy HX's field item-type
    combination rules; multiple values for the same field are OR'd (instead of
    impossibly AND'd).
  - Run-now hunts submit synchronously and report per-rule/per-search success (with
    search ID) or the exact HX error; scheduled hunts run via the scheduler.
  - Optional "Exhaustive search" toggle (off by default) scans full historical
    audit data instead of only the live event buffer.
  - The Hunt API preview shows the exact query payload with a readable
    "Copy payload" button.


ENTERPRISE SEARCH / TABLES
--------------------------
  - Search detail now includes the requested search criteria / indicator content.
  - Tables indicate the active sort column and direction.


VERSIONING
----------
  - Version bumped to 26.09.
  - The version number is now shown on the login page and in the main UI top
    navigation bar (available to all pages).


CODEBASE / INTERNAL (26.09)
---------------------------
  - New backend for Local Catalog groups (list / create / delete, per-rule group
    update) and IOC Hunt (submit, types, field mapping), plus the
    token-to-search-field mapping and the OpenIOC / query builders.
  - Added exhaustive-search support to enterprise search submission
    (restSubmitSweep, restSubmitQuerySearch) and the related task modules.
  - Server Rules table now reloads fresh (cache-busted) after a rule is added.


================================================================================
The following changes were introduced in 26.08-pre and are included in 26.09:
================================================================================

MANAGE RULES — IOC INDICATOR IMPROVEMENTS
------------------------------------------

View Rule
  - The View popup now displays the indicator name, description, category, and
    platforms at the top, even when reading conditions is blocked by the HX API.
  - When conditions cannot be loaded (HX error code 1101), the error popup now
    shows the full HX REST API endpoint URL, the HTTP status code, and the exact
    HX error code and message instead of raw JSON or a generic error.

Edit Rule
  - Fixed a crash (UnboundLocalError / HTTP 500) that occurred when opening any
    rule for editing.
  - The edit form now opens correctly, pre-populated with the rule name,
    description, category, and platform from the data already available in the
    indicators table — without making an additional API call that was blocked for
    many user roles.
  - When rule conditions cannot be loaded due to HX role restrictions (error
    code 1101), a clear warning banner is shown above the submit button explaining
    that conditions are empty and that submitting will overwrite them.
  - The HX REST API endpoint used for fetching indicator metadata is now shown in
    full (https://host:port/path) in all error messages.

Clone Rule
  - Fixed: Clone did not open the edit form. It now correctly opens a pre-filled
    form ready for creating a new rule based on the selected indicator.
  - Same fixes as Edit apply (correct indicator metadata, clear error messaging).

Create / Submit Rule
  - When rule creation fails, the error message now includes the full HX API
    endpoint URL, the HTTP status code returned by HX, and the exact HX error
    code and message. Previously the error was a generic "failed to create
    indicator" with no detail.

Conditions API
  - Added a new internal API endpoint (/api/v1/indicators/get/conditions) to
    fetch presence and execution conditions for a given indicator.
  - When fetching conditions fails, the response includes the full HX API URL,
    HTTP status, and HX error details so failures can be diagnosed without
    inspecting server logs.
  - Fixed a bug where the UnboundLocalError caused the indicator category edit
    policies endpoint to crash when the HX API returned an error.


MANAGE STREAMING RULES
-----------------------
  - No functional changes. View, Edit, and Clone continue to work as before.


UI / NAVIGATION
---------------

Font Size Controls
  - Added A- and A+ buttons to the top navigation bar for decreasing and
    increasing the content area font size.
  - The selected font scale is persisted in the browser's localStorage and
    restored automatically on the next page load (range: 70 % – 150 %,
    step: 10 %).

Error Handling
  - Rewrote the global hxtoolActionFail JavaScript handler to parse HX API error
    responses and display a structured, human-readable error message instead of
    raw HTTP status text. HX error codes, messages, and details from both
    presence and execution condition responses are extracted and shown.

Layout / Branding
  - Added viewport meta tag for correct scaling on high-DPI and mobile displays.
  - Updated top navigation to show the Trellix® brand name.


PYTHON / FRAMEWORK COMPATIBILITY
---------------------------------

  - Removed all `# -*- coding: utf-8 -*-` source declarations — redundant since
    Python 3 defaults to UTF-8 and these declarations are a Python 2 artefact.
  - Replaced `super(ClassName, self).__init__(...)` calls with the Python 3 form
    `super().__init__(...)` throughout (hxtool_logging.py, hxtool_tinydb.py).
  - Replaced all `str.format()` string formatting with f-strings across the
    entire codebase (hx_lib.py, hxtool.py, hxtool_api.py, hxtool_db.py,
    hxtool_logging.py, hxtool_mongodb.py, hxtool_scheduler.py,
    hxtool_session.py, and others).
  - Replaced bare `except:` clauses with `except Exception:` throughout
    hxtool_db.py to avoid silently swallowing BaseException subclasses
    (KeyboardInterrupt, SystemExit) — required by modern Python linting and
    best-practice guidelines.
  - Replaced deprecated `logger.warn()` calls with `logger.warning()` in
    hxtool_scheduler.py (`warn` was removed in Python 3.12).
  - Replaced deprecated Flask `session_cookie_name` attribute access with
    `app.config['SESSION_COOKIE_NAME']` required by Flask 2.3+.
  - Changed startup error messages that previously used `print()` to write to
    `sys.stderr` instead (hxtool.py, hx_lib.py, hxtool_db.py,
    hxtool_mongodb.py) so they are not swallowed when stdout is redirected.
  - Removed redundant parentheses from TinyDB `Query()` expressions throughout
    hxtool_db.py (e.g. `Query()['field'] == value` instead of
    `(Query()['field'] == value)`) — the extra parens were harmless but are
    not idiomatic with modern TinyDB.


CODEBASE / INTERNAL
--------------------

  - Version string updated from 4.8-pre to 26.08-pre.
  - Added hx_lib.restGetIndicator() — fetches a single indicator by category and
    URI name without appending pagination parameters that the single-item
    endpoint rejects.
  - Added _hx_error_detail() helper in hxtool_api.py to extract a human-readable
    error string from any HX API error response.
  - All HX API error messages now include the complete request URL
    (https://host:port/path) to aid diagnosis without server log access.


KNOWN LIMITATIONS
-----------------

  - Reading indicator conditions and creating/editing indicators in the Custom
    (unrestricted) category requires the HX REST API "Custom IOC" role to be
    granted on the HX server for the user's account. The HXTool Admin role does
    not grant this — it must be configured in HX platform user management.
    Affected operations show the specific HX error code and full API endpoint in
    the error message to aid escalation to an HX administrator.
  - Mandiant Intel and other restricted indicator categories are read-only by
    design in the HX REST API regardless of user role.
